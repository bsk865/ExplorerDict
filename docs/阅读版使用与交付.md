## 日常使用

1. 进入资料书架，打开已经同步的桌面文章，或添加 TXT、Markdown、PDF、DOCX、图片，也可以粘贴正文。
2. 原文划选词语，点击「探索这个词」；点击图片进入同级的图片探索对象。选择对象和浏览来源不会自动请求模型。
3. 点击「结合本文解释」「解释整张图」，或在小探对话框明确发送。关键词、图片、局部图片、文章话题的历史和草稿互相隔离。
4. 拖动图片框选后，点击「探索这一处」建立局部对象。选区相对于原图保存，缩放后保持一致。点击「选择整图」返回整图。
5. 回答里的来源按钮回到原文。局部对象返回原图时保留区域标记。收藏时保存当前理解与文章版本，之后可在「收藏与回顾」返回来源。
6. 「思维导图」使用全文生成、独立阅读、复核与纠错流程。失败保留原有图与草稿。精度只控制展开深度；收藏词高光，节点可查看原文依据。
7. 导图统一使用曲线、分支色与留白。画布仅显示组织结构，语义关系单独逐条阅读，避免跨图连线堆叠。可缩放、拖动空白平移；节点位置由布局统一安排，暂不提供自由拖拽节点。
8. 「导出导图」输出全精度 SVG 和完整原文关系 Markdown；「导出笔记」输出 Markdown 与完整 JSON，原图以数据形式附带，局部坐标和版本保留。JSON 是完整备份格式，当前没有 JSON 恢复入口。

## 同一模型的多模态检测

文字与图片共用一套 OpenAI 兼容 API 配置。首次使用从原桌面数据库只读继承；阅读版修改后的配置独立保存，不改写旧程序设置。Key 使用当前 Windows 用户的 DPAPI 加密，不发送给网页。

「主题与模型 → 检测图片理解」发送一张无个人资料的随机颜色、随机数量的圆形测试图。只有接受图片且识别正确才记为支持；网络、额度、解析等问题不能直接判为不支持。改动配置后检测结果失效。检测成功代表这次接口与简单识别通过，不保证所有图像任务准确。

本机实际验证：配置地址 `https://api.deepseek.com/v1`，配置名 `deepseek-chat`，服务端返回模型 `deepseek-flash`。实际图片检测通过；没有仅凭名称判断模型支持情况。已把相同配置的成功检测结果保存到生产阅读版设置。

## 数据与原文范围

- 原数据 `data/explorer_dict.sqlite3` 只读使用，交付同步前后 SHA256 一致；已有两篇原文已同步。只有有留档原文且词语能定位到原文的旧收藏进入新工作区；其他历史词条仍可通过原桌面取词程序查看。
- 新资料、图片字节、版本、对象、对话、草稿、生成失败证据保存在 `data/reading_workspace.sqlite3`。主题与阅读位置保存在独立的应用浏览器目录 `data/workspace-browser`。
- 给文章添加正文或图片会建立新版本，旧版本与引用保留，导图需重新生成。新版本复制已有对象和笔记，不把旧对话冒充新版本对话。
- 独立图片可「关联已有文章」，复用已存图像，生成目标文章的新版本。
- PDF 保存提取文本和每页原图；扫描页不伪造 OCR。DOCX 支持常见正文段落和内嵌位图，图注未自动匹配时明确提示。复杂 Word 图形、外链图片及原始分页排版不保证还原。
- 导图依据可提取正文与图注，图片内容在探索区单独理解；当前不会把看图解释自动改写成原文事实。超过 30000 字的正文要求拆分，不截断后冒充全文导图。
- 图片解释提供当前图片（局部对象提供裁切区域）、邻近原文与图注；文章话题在预算内提供正文。没有实现全文检索系统、模型上下文缓存或永久记忆，不承诺不再消耗上下文 token。
- 六主题与纸面/夜读沿用已有小探 v2 资产。用户文章图片不添加主题滤镜。

## 构建与回退

构建：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\build_reading.ps1`。构建环境需要 PyInstaller、Pillow、PyMuPDF，以及原项目客户端依赖。运行时位于 `_reading_runtime`，与旧 `_runtime` 分离。静态界面随阅读版包进入 `_reading_runtime/web`，不能只改根目录 `web` 就声称已更新打包版。

本次改动集中于 `app/workspace_store.py`、`app/workspace_server.py`、`web/`、`reading_desktop.py` 及独立构建文件；原程序只添加打开阅读版的入口。需要回退时可继续使用原 EXE；保留新数据库与完整阅读运行时，勿删除用户新增资料。源码通过本地 Git 留存，未推送 GitHub。
