## 产品方向与已经确定的要求

- 核心是模型自动理解材料并生成整篇文章的导图；收藏或划选词在全文图中高光，精度控制展开深度，不要求模型按关键词另造一张局部图。
- 关系依据必须来自原文；节点组织结构和原文语义关系需要可区分。不能为了消除孤立词凭空补线，也不能把没有语义线直接等同解释错误。
- 自动补全残缺划词，但补全必须有原文依据。无实际概念或关系意义的词可以建议排除，用户未授权自动删除收藏词。
- 关系线用易懂的短句或原文关系词，不强制显示“因果、归属”等专业分类。缺依据、补全歧义或生成失败需要明确提示。
- 质量优先，保留生成、复核、纠错和失败证据。模型自己获批不等于独立内容核查通过；联网资料不能用于凭空生成原文中不存在的关系。
- 视觉要求：曲线与直角线避免混杂，留足间隙，关系词位置清楚；用户对当前交互也不满意。
- 原快捷方式作为唯一阶段验收入口。更新必须说明实际同步内容，不能新建入口后宣称原入口已更新。

历史答复里的“第一种/1”没有完整选项文本时，不要重新推导具体需求；以当前代码、上述明确要求和后续用户反馈为准。

## API：本轮修复与证据边界

2026-10-14 历史解释失败为 `WinError 10061`，即连接被拒绝，未得到 HTTP 响应。长期实例保留旧代理快照是候选原因；没有故障当时的实际路由日志，根因尚非确证。系统残留本地代理端口不是所有请求实际走代理的充分证据。

新增 `app/api_transport.py`，由 `DeepSeekClient._post` 使用：每次尝试读取当前代理配置，建立独立 opener，记录实际路由和阶段；本地代理预检上限 0.3 秒。区分配置、代理、DNS、TLS、网络、超时、鉴权、付费、限流、模型、端点、服务端和响应结构错误，包括 HTTP 200 内的 error。

默认初次请求后最多重试 3 次，基础等待 1/2/4 秒并加 0–20% 抖动，单次等待最多 8 秒；永久错误不重试。尊重 Retry-After，超过上限或剩余预算则停止。默认传输总预算 `max(60秒, 配置超时)`，保留导图 120 秒能力；原生 DNS 等不能严格抢占，不承诺绝对硬截止。设置页连接测试只发一次。

解释面板提供重试进度和停止按钮。`ExplainService` 的取消与进度绑定 entry/token；取消不写成功缓存，切词不能串解释。退避可即时取消，但在途连接/读取可能等当前 socket 超时。

只读核查的生产设置：DeepSeek `https://api.deepseek.com/v1`，`deepseek-chat`，解释单次超时 25 秒，`api.reasoning_effort` 空，导图请求超时 120 秒。全文流程自行启用思考；不要因全局 effort 为空判断全文未思考。

本轮自编材料“原文依据”真实结构化解释成功，2043.6 毫秒；只读取配置、Key 仅内存解密，测试词未写生产库。这验证客户端请求，用户界面点击解释尚待实测。
