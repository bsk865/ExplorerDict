# 探索词典检修与交付规则

生效日期：2026-10-14。适用于取词、AI 请求、导图显示和桌面版本同步。

## 1. 先确认用户实际运行的版本

1. 解析用户指定的 `.lnk`，记录目标、工作目录、参数及快捷方式 SHA256。不得用另一个快捷方式的结果代替。
2. 记录运行进程的路径、PID、启动时间。重复双击可能只呼出旧实例；窗口关闭也可能只是收进托盘。
3. 在隔离数据目录运行原目标 EXE 的 `--diagnose`。核对 `module_origin`、关键模块 `module_sha256` 和 `paths.uia_helper_script`，不能只看 EXE 修改时间。
4. 本项目冻结入口加载 EXE 旁边的磁盘 `app/`，取词辅助脚本加载 `_runtime/scripts/`。新入口、构建规则或依赖变化必须重新构建并同步配套包。
5. 建议检修顺序：实际目标 → 实际进程 → 实际模块 → 实际数据 → 用户所见窗口或导出文件。

诊断示例（不建窗口、不启动取词、不读取生产配置）：

```powershell
$env:EXPLORER_DICT_DATA_DIR = 'D:\探索工具\探索词典\.tmp\isolated-diagnose'
$env:PYTHONDONTWRITEBYTECODE = '1'
$diagnosticProcess = Start-Process -FilePath 'D:\探索工具\探索词典\探索词典.exe' -ArgumentList '--diagnose' -WindowStyle Hidden -Wait -PassThru
$diagnosticProcess.ExitCode
Remove-Item Env:\EXPLORER_DICT_DATA_DIR
Remove-Item Env:\PYTHONDONTWRITEBYTECODE
```

## 2. 取词速度的判定

- 分别记录启动后第一次、暂停或全屏恢复后第一次、持续使用时的多次取词。
- 冻结计时边界：辅助进程启动到首个握手；手势排队；等待就绪；实际读取请求；松开鼠标到浮窗绘制。禁止把其中一段冒充完整响应。
- `Capture display elapsed_ms` 记录到 Tk 空闲绘制边界；真实可见延迟仍需要用户试用或屏幕记录。
- 握手成功才算 helper 就绪，不能仅凭子进程存活放行请求。启动、并发调用及恢复须共用准备状态。
- 保留前台 HWND/PID 和正文窗口校验。等待初始化后必须再核对前台，不能读已经切走的文档。
- 合并积压手势，处理最近有效手势。取词等待与请求共用当前 3 秒预算；超时明确记录 `helper_initializing`，不能在鼠标任务中追加同步 20 秒重启。
- 初始化超时后的本次手势目前可能未读取，不保证自动补读。记录负例后再决定是否修改恢复策略。
- WPS 普通 DOCX 正文已在先前版本实测；本轮首词速度由用户验收。不能扩写成 Microsoft Word 或所有应用均已通过。

## 3. API 审查与错误判断

按以下顺序检查同一次请求，避免额外付费探测：

1. 完整接口地址、模型名、Key 是否配置；接口地址中不得带凭据、查询参数或片段。
2. 当次请求实际使用的代理或直连路由。每次尝试重新读取代理，创建独立 opener，避免长期进程沿用 urllib 全局代理快照。
3. 已启用的本地代理是否可连接，预检最长 0.3 秒。不可达显示代理问题；不得擅改系统设置或静默绕过代理。
4. DNS、连接、TLS、超时分别判定。没有 HTTP 响应时，不得判断为余额不足。
5. 同时检查 HTTP 状态和供应商 `error.code/type`，区分鉴权、付费、限流、模型、端点、服务端错误。HTTP 200 中的 error 也必须检查。
6. 成功响应必须通过实际结构解析，不能只凭端口通或 HTTP 200 宣称解释可用。

2026-10-14 的历史 `WinError 10061` 表示连接被拒绝；长期实例保留旧代理是候选原因，缺少当时路由日志，不能写成已确证根因。后续以当次路由日志定位。

## 4. 重试和停止

- 默认初次请求后最多重试 3 次；基础等待 1、2、4 秒，附加 0–20% 抖动，单次等待最多 8 秒。
- 临时连接或 DNS 故障、408/504、429、500/502/503允许重试；配置、不可达本地代理、鉴权、付费、模型和 TLS 等永久错误立即停止。
- 解析 `Retry-After` 秒数及日期。服务器要求的等待超过上限或剩余预算时停止，不能擅自缩短后重试。
- 默认总传输预算为 `max(60秒, 单次配置超时)`；导图 120 秒请求保留长预算。原生 DNS 阻塞等不能严格抢占，不承诺绝对硬截止。
- 设置页测试连接只发一次；实际解释允许重试。等待显示次数和剩余时间，并提供停止按钮。
- 取消及进度必须绑定原词条和请求 token；切词不能串解释，取消结果不能写入成功缓存，也不能新增重复词条。
- 退避等待可即时取消；已经进行的连接或读取可能等到当前 socket 超时。

## 5. 导图样式与缓存

- 先区分设计预览、桌面画布、完整导出及旧图片。预览存在不等于实现完成；更新程序不会改写已经导出的图片。
- 桌面全文导图逐条浏览关系；完整导出显示全部关系，画面密度不同。检查两条路径后再判断漏关系或版本失效。
- 数据库缓存保存生成内容；布局缓存位于当前窗口内存，重新打开后按当前代码计算。不得为检查样式删除用户缓存、词条或强迫重新付费生成。
- 原文关系标签须保持原意，避开卡片、全部连线及其它标签。离线几何检查不代替原文核查和真实交互验收。
- 保留待改进项：长线归属追踪、完整长图缩小后的字号、预览与桌面样式差异。不能把“模块导入成功”写成“设计效果已满足”。

## 6. 同步、留存和验收

1. 先完成构建和相应测试；记录跳过项目及验收边界，不把多轮测试数量相加。
2. 正常退出旧实例，再确认无进程。活跃实例不得直接覆盖运行时；旧版本的 EXE 和整个 `_runtime` 必须保留可恢复备份。
3. 同步完整 EXE + `_runtime`；逐文件核对 SHA256，源码 helper 与打包 helper、原生 DLL 同时核对。
4. 同步前后核对原快捷方式和生产 `data/`。词库、设置、密钥密文保持原位；测试用隔离数据库。
5. 从同步后的原目标执行隔离诊断，留存实际模块路径和哈希，再交给用户从原快捷方式验收。
6. 在 `docs/验收记录/` 留存脱敏证据与负例，在 README、软件说明、改进清单和 AI 对话记录添加入口；不能只记在被忽略的交接文件中。
7. 本地提交保留恢复点；GitHub 上传按用户约定执行，本地提交不称为已推送。

日志和入库证据不得包含 API Key、代理密码、生产响应全文或用户材料。允许记录目标路径、路由 host:port、阶段、错误类别、HTTP 状态、次数及耗时。
