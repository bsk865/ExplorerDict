# 探索词典：信息存储与上下文说明

更新日期：2026-10-19。说明对象是探索词典 APP 的模型请求，不是开发助手自身的对话。

## 两种容量

本机数据库保存历史资料；模型上下文是单次请求临时携带的材料。二者不同：保存了一整篇文章、很多对话，不代表每次请求全部发送。软件通过配置的 API 调用远程模型，不下载模型权重。服务商是否留存请求取决于其服务政策，本机数据库不能反映服务端留存情况。

## 实际数据位置

默认目录：`D:\探索工具\探索词典\data`。

| 保存位置 | 保存的数据 |
| --- | --- |
| reading_workspace.sqlite3 / articles | 提取的文章正文、段落结构、版本、来源、正式导图和质量报告；被替换的版本可能仍保留，用于旧引用 |
| reading_workspace.sqlite3 / assets | 导入或页面提取后经处理的图片二进制；不保证与原始上传文件逐字节相同 |
| reading_workspace.sqlite3 / objects | 关键词、图片对象、图片区域坐标、收藏状态、个人笔记和划选上下文 |
| reading_workspace.sqlite3 / sessions | 按文章版本及对象区分的问答消息、输入草稿、笔记、回答引用；新版本还记录最近一次成功问答的模型标识及用量数字 |
| reading_workspace.sqlite3 / attempts | 导图阶段草稿、复核意见、失败原因；不是每次 HTTP 完整响应的逐字留档 |
| reading_workspace.sqlite3 / map_parts | 已通过复核的长文分段导图缓存，按正文版本、模型及规则等区分，供重试复用 |
| reading_workspace.sqlite3 / source_chunks、source_indexes | 用于检索的正文片段、图注或视觉描述及索引信息 |
| reading_workspace.sqlite3 / settings、capture_links | 工作区设置、按接口和模型区分的上下文上限、主界面与原生词条的对应关系 |
| explorer_dict.sqlite3 | 原生浮窗的文章分组、词条、上下文、原文留档、解释与解释缓存、追问历史、原生导图相关记录及配置；与主界面有部分同步副本 |
| data/logs | 运行、启动和故障日志；现有取词日志可能包含所划选词语及应用/窗口信息 |
| data/backups | 更新或维护时创建的数据库/脚本备份；删除当前文章不会同时删除旧备份 |
| 用户选择的导出位置 | 主动保存的 PNG、SVG、笔记或草稿文件；桌面保存对话框由用户选择位置 |

API 密钥通过 Windows DPAPI 加密保存；这不等于整个 SQLite 数据库都经过加密。文章、对话、笔记属于普通本地数据库内容。主题等界面偏好还可能保存在桌面内嵌浏览器的本地存储中。

导入 DOCX/PDF 后，工作区主要保存解析后的内容和图片，不是对原文件的通用完整备份。未成功解析的部分不应视为已保存。

## 每次模型请求包含什么

### 主界面问答

- 当前问题：当前实现最多取前 6000 个字符。
- 当前话题最近 12 条消息（不是固定 12 轮问答）；这些历史消息本身没有统一总 token 裁剪。
- 本次检索出的原文及图像描述：主要材料预算 18000 字符，通常最多 10 个检索项；另可能附加对应页面图片。
- 支持视觉时，本次最多附带 3 张图片，发送前缩放至不超过 1800×1800；选区图片会裁剪。图片 token 无法由文件字节数直接确定。
- 系统说明、来源标签等也占用 token，不能只计算聊天正文。
- 引用核验失败时可能再次请求修正，修正请求还包含第一次回答。

主界面不会因为本机有很多篇文章就自动把它们全部发送。选择资料书架范围时先检索，再发送命中材料。

### 导图

独立阅读、生成、复核是分别构造的模型请求，不共享主界面问答历史。每个请求可能包含原文、划选词、待复核草稿、阅读清单或纠错意见。正文超过 30000 字符时分段，常用段长 24000 字符、重叠 500 字符。最多三轮纠错。后台自动预读方案尚未在本次改动中落地。

### 原生浮窗追问

使用另一条构造路径，包含当前词、上下文、解释、本次问题与有限历史；历史还受字符预算约束。不能把主界面的最近 12 条规则直接等同于原生浮窗规则。

## 上下文圆环如何解释

主界面对话输入区的圆环表示“上次请求”的用量，点击可查看详情及设置当前模型的上限。

- 接口提供输入和输出 token 时，以二者之和除以用户填写的模型上下文上限，显示比例。它不是多次调用累计用量或费用统计。
- 接口没返回用量时，仅按文字长度给粗略估算（字符数除以 2，加消息开销）；不同语言、模型分词可有较大差异。图片用量不包含在该估算中，因此不据此显示百分比。
- 上限未知、没有旧版用量记录、模型/接口已更换时显示“—”，不推测模型上限。
- 填写的上限按接口和模型保存，只用于展示，不会自动截断原文。接近上限应减少本次材料或另开话题；服务商仍会拒绝超窗请求。
- 圆环是最近一次请求的快照，不是下一次发送前的精确预算；新输入、下一次检索、引用纠错都会改变实际请求大小。
- 导图和图片处理等后台任务在进度面板显示当前阶段的文字估算或接口用量；这些阶段不算入聊天圆环。
- 新的用量记录仅保存数字和模型标识，不因此新增保存请求全文、图片 base64 或 API 密钥。

## 本次验证边界

通过受控响应验证真实 usage 优先于估算、图片 base64 不误算为文字 token、用量元数据不含问题正文和密钥；通过浏览器验证未知上限、设置比例、模型切换失效和重载保留。没有为此发起付费模型请求。尚未实现统一的模型 tokenizer、发送前精确预算或全应用自动裁剪。
