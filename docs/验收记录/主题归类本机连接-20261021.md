# 主题归类的本机连接修复

## 问题与范围

用户反馈新建主题、拖动文章归类出现fetch失败。两个入口分别调用本机study/themes和study/assign，只写SQLite，不调用模型或互联网服务。

代码发现可导致此症状的生命周期缺陷：窗口最小化后页面停止capture状态轮询，而headless服务10分钟没有请求就退出；桌面壳没有同步关闭。恢复窗口后请求旧端口，原始fetch异常直接显示。缺少用户该次失败请求的日志，不能断言这是当次故障的唯一原因。

## 修复

- 桌面壳启动服务时传入自己的PID。服务根据所属进程是否存活决定退出，不再因页面闲置退出；所属进程异常结束后也会回收服务。独立服务保留原有闲置退出规则。
- 前端区分本机连接中断、响应不完整和后台业务错误，不自动重放写请求。未收到响应不等于未写入，提示检查结果避免重复添加。
- 新建主题保存期间禁用重复提交，失败保留当前表单内容，并在弹窗内部显示错误，避免提示被弹窗背景模糊遮挡。此项保留指当前窗口内的输入，不代表未提交表单已持久化到磁盘。

## 验证

- 生命周期、主题管理、工作区专项31项通过。模拟一小时无浏览器请求：桌面所属进程存活时服务继续，独立闲置服务退出；所属进程退出时回收服务。
- Browser plugin not available，使用现有Playwright与Edge。阻断浏览器外网请求，实际新建主题、拖入文章、刷新验证关联仍在；未发起生成类API请求。
- 模拟本机连接拒绝，验证中文错误、当前输入保留、保存按钮恢复、连续提交只发出一次请求。脚本：tools/check_local_themes.cjs。
- 测试没有禁用整台机器的网络；离线性由调用链检查、浏览器外网阻断与未调用模型入口共同验证。
