# 原生版构建与安装

原生版与旧版使用不同的安装目录和卸载标识。迁移期间保留旧版程序及原始资料，验收进度见[原生桌面迁移](原生桌面迁移.md)。

## 构建

在项目根目录执行：

```powershell
.build-env/Scripts/python.exe -m pip install -r tools/build-requirements.txt
.\tools\build_native.ps1
.\tools\build_native_installer.ps1
```

`build_native.ps1` 默认先从当前源码重建 UIA 辅助库和悬浮组件，再生成原生独立运行目录。辅助库编译到独立构建目录，避免覆盖正在使用的开发组件。悬浮组件记录源码哈希与 EXE 哈希，主包构建核对后才复制，避免主界面更新而浮窗仍为旧版。只有组件与当前源码匹配时才可用 `-ReuseCompanion` 省去重建。最后的安装器命令先审计包内容，再编译中文安装器。安装器默认输出到 `artifacts/native-installer/ExplorerDict-Native-1.0.0-Setup.exe`。版本可用 `-Version` 指定。

主界面与浮窗分别携带同一份主题 CSS，构建指纹包含 CSS 与打包配置；缺少主题资源时包审计失败。可执行 `.build-env/Scripts/python.exe tools/check_companion_appearance.py <浮窗EXE路径>`，在独立资料目录用实际 Tk 控件检查六套主题的明暗切换、重启恢复、输入保留和不弹出窗口，不启动取词监听或模型请求。

安装器编译器为 Inno Setup 7.1.0，默认查找 `artifacts/tooling/inno/ISCC.exe`，可通过 `-Compiler` 指定其他位置。当前编译器以便携模式放在项目构建目录，没有注册文件关联。下载来源为 Inno Setup 官方 GitHub 发布，下载文件 SHA256 为 `0362a383ed217d4c4239b5933866dd96d3eb2102737da92f80f6057a4b40df2f`，数字签名已验证。当前工具按非商业用途运行；商业发行时须采用符合其许可的构建环境。

## 安装与数据

- 默认安装到当前用户的 `%LOCALAPPDATA%\Programs\ExplorerDictNative`，无需管理员权限。
- 开始菜单入口为“探索词典原生版”，桌面快捷方式由用户勾选。
- 初次安装默认使用安装目录下的 `data` 文件夹；已有存储位置配置继续生效。
- 安装包仅包含程序、运行库、美术资源和本地模型，不包含用户资料数据库。
- 卸载保留 `data` 以及用户生成的存储位置配置；外部资料目录也不列入卸载清单。
- 安装器不自动读取或搬动旧版数据。正式迁移前仍需完成资料交接与回退验收。

试用目录之间可通过各自的 `storage-location.json` 指向同一资料目录。启动相同构建会唤起已有窗口；启动不同构建时，新程序等待旧窗口保存退出并释放单实例锁，再打开所选版本。若旧窗口仍在保存，界面会提示等待，不会强制结束进程或悄悄唤起其他版本。历史旧包本身不具备此切换逻辑，测试新版请使用新构建的入口。

当前安装器和应用尚未配置发布者代码签名。Windows 的信誉提示与网页引擎依赖是不同问题，安装器不会关闭系统保护。

## 隔离验收

```powershell
.build-env\Scripts\python.exe tools/check_native_installer.py artifacts/native-installer/ExplorerDict-Native-1.0.0-Setup.exe
```

该命令先检查是否已有原生版安装注册；若存在则停止，避免替换已有安装。测试在 `artifacts/native-install-checks` 的新目录中安装，关闭图标创建和完成后的自动启动，运行应用工作流验证，再覆盖安装并卸载，核对资料保留结果。日志和结果留在该目录中。

受限执行环境中可增加 `--isolated`，只验证文件安装、启动、覆盖更新和卸载保留，不写开始菜单与卸载注册表。报告明确记录 `os_registration_tested=false`，不能替代普通安装验收。直接运行安装器仍默认创建系统注册信息。

此检查覆盖当前版本重装与卸载保留，不替代跨版本数据库迁移、普通双击启动、取词组件及联网模型工作流的验收。最终状态以实际验收记录为准。

检查两个已构建版本之间的覆盖升级时，可传入 `--upgrade-from <旧安装器路径>`。先安装旧包，再用所选新包覆盖，核对原文、笔记、按文章保存的译文、存储配置和数据库文件保留，并分别运行安装后及升级后的实际EXE流程。增加 `--isolated` 时仍不包含系统注册；也不代表更早版本的所有数据库格式均已迁移。

## 存储位置验收

```powershell
.build-env\Scripts\python.exe tools/check_native_relocation.py artifacts/native-build/dist/探索词典-原生版/探索词典-原生版.exe
.build-env\Scripts\python.exe tools/check_native_relocation.py artifacts/native-build/dist/探索词典-原生版/探索词典-原生版.exe --with-companion
```

该命令在artifacts/native-relocation新建带标记的合成资料，离屏打开设置并点击保存位置，经应用退出时的apply_pending复制后，校验数据库内容、完整性、附件和原目录保留。随后启动第二个独立进程，由隔离的storage-location.json选择新目录，核对文章、笔记和标注。省略EXE参数时验证源码入口。

验证入口拒绝未标记目录或指向隔离目录之外的配置，且不修改正式存储配置。默认流程不启动悬浮取词组件，报告capture_lifecycle_tested=false。

增加 `--with-companion` 时，通过应用的启动接口装配实际取词组件、数据库和单实例锁，并经正常退出事件关闭组件后迁移；重新启动的两个组件仅依赖保存的存储配置读取新目录。额外核对词条、主题、图片、按文章保存的译文及导图修改。组件窗口隐藏，不启动全局取词监听或操作桌面，报告capture_lifecycle_tested=true不表示跨应用划词已经验收。源码联动记录：`artifacts/native-relocation/relocation-_hcp03hv/workflow-verification.json`；打包主界面及组件联动记录：`artifacts/native-relocation/relocation-9vr10a7d/workflow-verification.json`，两个组件均为frozen=true。
