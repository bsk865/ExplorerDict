# 协作设计

探索词典的开发将使用场景、数据关联与具体交互作为协作任务的中心。AI辅助完成代码生成、问题定位与重构，开发者负责定义目标、选择方案、判断结果并组织交付。

## 组织任务上下文

每次修改提供相关模块、现有数据结构、用户操作和出现的问题。涉及阅读的任务携带文章版本、选区与会话归属；涉及桌面联动的任务说明主界面与浮窗共享的配置和启动关系。任务范围随功能模块划分，已有接口和资料成为连续开发的基础。

## 用行为约束表达意图

资料库问答的目标表达为“已加入的资料默认可查阅，选择范围用于缩小检索”；翻译的目标表达为“源语言、目标语言、译文与任务属于当前文章”；发现更新的目标表达为“新增和修改分别显示，重复读取保留已有列表”。

这些表述落到可观察的结果：用户无需反复选择文件，切换文章后恢复各自译文，刷新没有变化时能看懂更新状态。功能约束因此直接连接数据结构、界面操作与检查动作。

## 保持代码职责清晰

页面控制器负责展示和用户动作，业务服务负责资料、检索与任务，存储层负责持久化和事务。AI生成的修改沿用这些职责，例如问答页调用统一检索服务，主界面和浮窗读取共同主题配置，全文接入复用同一文档读取流程。

## 从反馈继续迭代

实际反馈带来更具体的判断条件：等待时间拆分为排队、网络和生成；同一请求保持可取消；城市恢复先于联网刷新；发现新增数与读取记录数分别统计。修复围绕这些条件推进，并保留既有文章、笔记、译文和引用。

## 在应用中组织模型任务

应用中的资料问答先检索相关原文，再把问题、会话及依据组织为请求。导图采用研读、生成和复核阶段，分别管理输入与进度。规划把目标、可用时段和已有安排组织为结构化任务，保存前核对时间与资料关联。

上下文预算、推理强度和模型服务由设置管理。任务状态和实际结果返回所属文章或会话，用户可以继续阅读、停止任务或保留草稿。

## Prompt与代码的对应关系

技术设计第16章介绍实际任务的输入组织、结构约束与保存校验，第17章串联三条真实协作案例。下面给出开发时的入口：

| 任务 | 模型约束与代码职责 | 实现入口 |
| --- | --- | --- |
| 资料问答 | 材料标记原文、笔记和片段身份；回答引用本轮S编号，代码核对引用和资料版本 | `app/library_assistant.py`、`app/retrieval.py` |
| 文章翻译 | 指定翻译方向，把正文作为待译材料；代码按文章与输入身份分段保存和恢复 | `app/translation.py`、`app/native/translation.py` |
| 导图生成 | 分别研读、生成与复核；代码核对节点、逐字引用、关系及输入版本 | `app/article_map.py`、`app/long_article_map.py` |
| 学习规划 | 输入目标、日期、已有安排与资料，返回结构化任务；代码核对时间、冲突和整批保存 | `app/study_advisor.py`、`app/study_hub.py` |
