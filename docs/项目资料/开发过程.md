# 开发过程

探索词典从跨应用划词工具逐步发展为连接阅读、资料问答与学习整理的桌面应用。开发沿着真实阅读中的问题推进：先保留词语与上下文，再让资料可以被查找和追问，随后将理解转化为笔记、导图和计划。

## 从使用场景建立功能

需求围绕用户动作表达。例如，阅读时应能直接提问，资料库中的文章应自动参与全库问答，译文应跟随所属文章保存，主界面与浮窗应共享资料和主题。这些动作确定了文章、选区、会话、引用和笔记之间的关联。

实现以模块为单位推进：先明确输入、输出和保存对象，再复用已有服务完成界面接入。实际使用反馈进入下一次修复，形成“场景需求、模块实现、交互复核、定向修改、版本交付”的循环。

## 三条核心迭代

### 资料库问答与本地检索

阅读材料逐渐增多后，单篇问答扩展为资料库问答。关键词检索与本地向量检索共同查找相关片段，回答携带可返回原文的引用；新增文章自动进入全库范围，范围选择保留为用户主动筛选。

围绕这条链路，后续补齐改名与正文变化后的索引更新、多个问题分别寻找依据、原句定位及会话接续。

### 后台预读与模型请求

用户在阅读过程中关注等待时间，开发因此加入后台预读、相同请求合并和前台操作优先。网络临时失败后，受管理请求在时间预算内重试；停止操作与具体任务绑定，切换资料时分别保存进度。

这一过程把排队、传输、生成和取消作为不同状态处理，让界面可以继续阅读，同时显示正在进行的任务。

### 学习规划与任务记录

阅读与笔记积累后，用户需要把目标安排到后续时间。规划模块结合已有日程、学习偏好和资料关联生成任务，保存后展示完成记录。日程变化引发冲突时，应用基于最新安排重新分配时间，保留任务内容与时长。

## 从功能到连续体验

随着功能集成，开发重点转向阅读流程的一致性。文章翻译归入阅读工具栏并按文章保存；问答嵌入原文侧栏；发现页接入不同平台的内容与原站封面；主界面和浮窗共用资料、模型配置和主题。

原生主界面通过PySide6直接调用业务服务，悬浮取词保留独立桌面组件。同步构建把两个入口作为同一交付的组成部分，阶段版本固定源码与程序包的对应关系。

## 修改与交付方式

检查围绕修改所影响的行为展开：数据归属、页面状态、原文引用和保存结果。界面改动通过实际窗口查看，程序交付同步构建主界面与浮窗，再完成关键页面流程。

开发记录保留日期和提交位置。三条原始协作链保留连续对话、时间与附件；[导出索引](原始对话/导出索引.json)记录文本摘要值，[导出工具](../../tools/export_prompt_chains.py)提供整理方式。较早的功能文档和运行记录集中保存在[历史资料](../history/README.md)。
