# 探索词典 · 技术设计

Windows 桌面阅读与本地学习空间

版本：1.0.20261025.3　更新：2026-10-25

探索词典将多源发现、跨应用划词、文章阅读、翻译、资料问答和学习整理连接起来。用户从一个问题进入原文，在阅读现场保留上下文，再把理解整理为笔记、导图和计划。

![文章旁的阅读与问答](../screenshots/reading-space-20261024/public-paper-reader.png)

## 1. 应用场景与设计理念

课程学习需要把概念理解留在讲义旁，论文阅读需要跨语言对照并反复核对原句，专题探索需要把不同平台的线索放到共同资料库。探索词典以文章为中心组织这些任务，保留来源、版本、选区和后续理解之间的关系。

软件通过两个入口承接阅读：主界面提供完整的资料与学习空间，浮窗承接外部应用中的划词。两者共用资料、模型设置与主题。用户可以先做一次短暂探索，再回到主界面继续阅读和整理。

设计围绕三个连续关系展开：问题关联出现的位置，回答关联原文依据，理解关联后续行动。文章旁问答、按文章保存的翻译、带引用的导图以及关联资料的计划共同维持这些关系。

资料保存在本机，用户可选择模型服务、推理强度和问答预算。不同平台的内容交错呈现，来源筛选、兴趣和屏蔽词让用户主动安排信息入口。六套主题与明暗模式贯穿两个交互入口。

## 2. 功能与阅读流程

发现页接入RSS/Atom、公开文章链接和论文来源，提供兴趣排序、来源管理、收藏、最新发布与本次更新。更新比较已有条目，分别统计新增与修改；封面采用原订阅或网页资源。

全文接入共用文档读取流程。网页、直接PDF、arXiv和公开声明PDF的论文详情页转换为文章块，保留来源和可用原件。文章进入本地资料库后参与检索、问答与整理。论文摘要以独立内容类型保存。

阅读页提供文内查找、原文标注、随文笔记、图片缩放与框选。用户可以在文章工具栏翻译，在侧栏提问，在导图中整理结构。文章、词条和内容管理支持回看探索记录，阅读笔记导出汇集原文、标注、问答引用、心得和译文。

学习规划接收目标、日期和偏好，结合已有安排生成任务。任务关联资料，并通过待办、完成进度和统计进入后续学习。

## 3. 系统架构与数据流

![系统架构](../images/architecture.png)

界面层采用Python和PySide6。`native_desktop.py`装配主窗口，`app/native/`组织页面与控制器。页面通过`NativeService`调用既有业务服务，工作线程承接联网和模型任务。

悬浮组件由`bootstrap.py`及`app/ui/`装配，通过Windows辅助功能接口读取选区与上下文。主界面和组件独立运行，通过本地事件协调呼出与退出，共用资料目录和持久化偏好。

业务层包含资料接入、混合检索、问答、翻译、导图、学习规划与内容管理。共享服务让不同入口遵循同一套资料保存和来源规则。任务结果绑定所属文章、来源或会话，界面根据具体任务更新状态。

存储层以SQLite和资料文件为基础。阅读工作区保存文章、版本、对象、会话、笔记、计划和向量索引；词条库保存外部划词与共享配置。图片、下载原件和发现缓存按用途组织在资料目录中。

| 模块 | 主要职责 |
| --- | --- |
| `app/native/service.py` | 原生页面到业务服务的连接 |
| `app/workspace_store.py`、`app/db.py` | 阅读资料、词条与共享设置 |
| `app/reader_source.py`、`app/native/materials.py` | 全文接入、文档信息与原件 |
| `app/retrieval.py`、`app/semantic_library.py` | 关键词、语义检索与融合 |
| `app/library_assistant.py` | 资料问答、会话与引用 |
| `app/request_supervisor.py` | 请求调度、合并、取消与重试 |
| `app/study_hub.py` | 学习笔记、计划与完成记录 |

## 4. 混合检索与原文引用

本地资料问答由范围选择、资料检索、模型回答和引用定位组成。全库会话动态读取已入库资料，本文会话聚焦当前文章，用户可按需要缩小范围。抓取上下文作为有来源的片段参与检索。

关键词检索覆盖标题和正文，语义检索使用本地`multilingual-e5-small`向量模型。文章与个人笔记进入增量索引，资料变化后重新计算对应内容。两类召回采用倒数排名融合，结合当前阅读位置组织结果。

检索结果携带文章、版本、块标识、字符位置与原句。系统选取相关片段，再将问题、会话和依据组织为模型请求。一次提出多个明确问题时，分别寻找依据并分配材料空间。

模型回答中的引用通过当前来源映射和原文片段核对后保存。阅读页根据块和字符位置回到原句，富文本使用可见正文的字符映射。历史会话保留当时的依据快照，文章修改后仍可查看原来的理解过程。

作答期间，应用核对相关正文和已纳入笔记的变化。数据归属贯穿检索、生成和保存，让回答继续对应用户提出问题时查阅的材料。

## 5. 翻译、导图与学习规划

翻译属于文章工具。源语言、目标语言、原文草稿、译文和任务按文章保存；长文按段落边界分段，完成部分持续保留。用户可以停止、继续、复制和导出，切换文章时恢复各自状态。浮窗文字与发现摘要按其来源分别保存。

导图提供正文与图文两种输入方式。生成流程先研读并记录原文依据，再生成结构，最后复核。长文分段保存已完成结果，任务恢复时复用有效分段。节点和关系保留原文依据，个人编辑保留自己的标记。

导图画布支持层级浏览、分支展开、缩放、节点文字编辑、增删节点、调整层级和关系编辑。文字与布局随文章保存，撤销与恢复帮助整理；导出包含完整结构和依据。

规划将学习目标、每日时段、分钟预算及已有任务组织为结构化输入。保存时核对时间冲突和任务关联，在同一事务内完成相关写入。若日程在生成期间变化，应用读取最新安排重新分配时间，保留目标、任务内容和时长。

这些功能通过共同的文章标识连接起来：译文帮助阅读，问答形成理解，导图梳理结构，笔记沉淀观点，计划安排下一步。

## 6. 状态管理与桌面体验

页面控制器与后台任务分别管理生命周期。切换页面后，任务结果更新所属数据与可用操作；已经打开的文章或详情保留阅读位置。草稿、语言、引用与导图编辑按文章或会话分别保存。

模型调用通过请求管理器组织，包含实际连接、排队、共享请求、取消和重试。相同进行中的请求可以合并，前台操作优先于后台预读。临时故障在任务预算内重试，停止状态绑定具体请求，结果再交回对应任务。

主界面与浮窗共同读取主题、明暗模式、模型和存储位置。构建流程同步重建两个入口，并记录源码与程序指纹。启动不同构建时，新程序等待旧实例正常保存退出，再打开所选版本。

界面使用统一主题的按钮、下拉框、表单和文件面板。问答、翻译和导图嵌入当前阅读流程，状态文案说明正在进行的操作与可用结果。城市等偏好先从本地恢复，再进行网络刷新。

## 7. 开发流程与协作方法

开发以实际阅读行为定义任务。例如，资料库问答默认查阅已加入的资料；翻译随文章保存；发现刷新区分新增、修改和重复读取。这些行为同时约束数据结构、服务接口与界面状态。

任务上下文包含相关代码、现有资料结构、触发步骤和目标结果。AI辅助完成模块实现与问题定位，开发者决定产品方向、职责划分和取舍，并通过实际使用反馈继续修正。

功能任务沿“需求表达、模块实现、实际反馈、定向修复、版本交付”推进。资料问答、请求管理和学习规划各自保留完整的协作记录；问题反馈与相应模块提交可以连贯查阅。

检查围绕改动行为展开：资料归属核对保存结果，引用核对原句，界面查看实际窗口，构建核对主界面与浮窗。阶段交付固定源码与程序包，使用说明和版本记录跟随交付更新。

开发过程与原始协作记录见[开发过程](开发过程.md)和[记录目录](原始对话/README.md)。

## 8. 运行、数据与项目维护

Windows用户可以下载免安装包，解压后直接启动。程序包提供运行环境与本地向量模型；阅读、标注和整理在本机完成，问答、翻译、导图和规划使用设置中选择的模型服务。

源码运行使用Python3.14和PowerShell。`requirements.txt`固定运行依赖，准备脚本创建环境、校验本地模型并编译辅助库。环境变量示例支持选择独立资料目录，运行与构建步骤分别保存在开发文档中。

本地模型固定revision和SHA256。程序发布提供ZIP与摘要校验文件；源码提交、依赖、模型版本和文档共同描述可重复的运行环境。模型生成文本随服务与输入而变化，数据结构、来源关联和状态规则由本地代码管理。

资料目录包含文章、笔记、词条、对话与附件。密钥通过Windows DPAPI保存，备份时退出程序后复制完整资料目录。模型请求发送当前任务所需材料，服务端处理方式遵循用户选择的服务政策。

项目通过Issues收集问题和建议，代码修改围绕单一行为提交，涉及界面时附上实际画面。当前版本与后续方向集中在版本进展，历史规格和运行记录按阶段归档。
