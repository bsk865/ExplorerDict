## 1. 产品目标与使用场景

探索词典围绕“发现一条线索，读懂一篇文章，留下自己的理解”组织功能。核心对象是带来源的文章：提问关联阅读位置，回答关联原文依据，译文、笔记和导图关联所属文章，计划关联后续学习。多个入口共同使用这套关联，减少资料在不同工具间反复搬运。

课程学习时，用户导入讲义或文字资料，在原文中查找和标注概念，用“问本文”继续追问，再把结论写成笔记或安排复习。论文研读时，用户保存公开论文与原始PDF，结合语言翻译、图片浏览、原文引用和导图整理理解文章。专题探索时，多平台新闻和论文进入共同发现页，用户选择值得精读的全文加入本地资料库。

跨应用阅读由划词浮窗承接。用户可以在其他应用中抓取词语和上下文，保留来源后继续解释，再进入主界面取得全文、组织文章与学习记录。主界面承担完整阅读和管理，浮窗承担短暂探索。两者共享资料目录、模型配置和主题，分别管理当前窗口里的交互状态。

设计采用四个原则：以原文为中心；把来源和个人理解保留下来；让任务结果归属于文章或会话；让使用偏好持续保存。发现页同时提供兴趣排序、平台交错和主动来源筛选，兼顾熟悉方向与陌生线索。原站封面、文章标题和发布时间帮助用户判断内容，而理解结果逐步沉淀为自己的笔记、结构与行动。

本地阅读、标注、整理和记录查看可独立进行；发现更新、网页获取、天气和模型任务分别访问相应网络服务。用户在设置中选择模型供应商、模型、推理强度和问答预算。图片理解取决于所选模型的实际图片输入能力。

这些功能以资料和阅读行为串联。翻译是文章工具；全库问答直接读取已加入资料；主题是组织方式；个人补充有自己的标记。详细操作按入口放在[使用指南](../使用指南.md)和[文档导航](../README.md)。

## 3. 系统架构与执行入口

![主界面、浮窗、业务服务与存储](../images/architecture.png)

原生主界面使用Python和PySide6。入口native_desktop.py建立应用、处理资料目录与实例协调，再装配NativeService和NativeWindow。页面控制器放在app/native/，按阅读、发现、问答、翻译、导图、规划和内容管理划分。控件层负责显示和收集操作，业务层负责检索、模型任务和保存规则。

主界面直接调用Python业务服务。既有Workspace对象继续承接导入、文章、模型和任务规则；app/workspace_server.py中的业务类也可被直接复用。原生界面的普通操作不经过本地HTTP请求，当前主界面也不依赖Qt WebEngine。web目录保留共享主题、图标资源和早期阅读界面。

浮窗由bootstrap.py及app/ui/装配，通过Windows辅助功能与桌面组件读取选区。浮窗和主界面是独立进程，共享文件和数据库中的持久化状态，通过本地激活事件和交接记录协调启动、返回与退出。页面中的临时草稿和正在编辑的控件分别属于各自窗口。

联网和模型任务在工作线程执行。页面发起任务后得到进度、结果或错误；结果按文章、来源或会话标识保存，再由对应控制器刷新。页面切换不会改变任务的所属资料，长时间任务可停止，已有有效结果继续保留。

主要职责边界为：NativeService连接界面与业务；WorkspaceStore及Database处理本地保存；检索模块选择依据；模型客户端处理供应商通信；RequestSupervisor处理请求资源；StudyHub组织笔记和计划。新的功能优先复用这些服务，并沿用现有文章与会话关联。

## 4. 数据模型与一致性

文章包含稳定id、正文版本、标题、来源、段落块及可用附件。文字块保留正文或安全富文本，图片块引用资源id，页码等定位信息随块保存。正文内容形成指纹，相同内容导入可复用已有文章；更新资料时保留可追溯的版本关系。

| 数据对象 | 保存位置与关联 |
| --- | --- |
| 文章与版本 | reading_workspace.sqlite3中的articles；保存正文块、来源、内容指纹及版本关系 |
| 图片和探索对象 | assets保存图片；objects以article_id、version、block关联词语、整图或归一化选区 |
| 会话与任务状态 | sessions、settings及任务记录；保存消息、草稿、依据快照、翻译分段、阅读与导图状态 |
| 笔记、计划与活动 | study_notes等学习表；关联文章、版本、日期、任务与完成记录 |
| 关键词与向量索引 | source_chunks、rag_documents、rag_vectors；记录块位置、内容指纹、模型和向量 |
| 划词词库与配置 | explorer_dict.sqlite3；保存词条、模型配置、共享阅读外观等 |

图片经方向校正、大小检查和规范化后按内容摘要保存。选区坐标使用原图的归一化位置，显示尺寸变化后仍能定位。词语探索对象必须存在于所属原文块中，图片对象和选区必须引用相同原图。

会话保存回答当时采用的原文依据，包含文章、版本、块、字符范围和原句。检索前后及模型回答保存前再次核对正文、标题、探索上下文和已纳入笔记的状态，避免在生成期间改动资料后将旧结果写回新资料。

数据库连接由上下文管理器关闭；关联保存使用锁或事务组织。学习计划整批提交，语义索引完成有效性检查后发布。删除文章会清理关联内容，删除主题保留文章，删除对话保留独立笔记。详细影响在操作时展示，并由内容管理规则统一处理。

## 5. 发现、兴趣与多源订阅

发现页聚合RSS/Atom和公开文章入口，分别呈现新闻与论文。默认来源包含中文科技与社区、国际新闻、科学传播、学者观点和开放论文；用户可增减、暂停来源，粘贴网站地址查找可用订阅入口，也可直接收集公众号、浏览器文章或PDF公开链接。

推荐在本机计算。明确填写的兴趣获得基础权重，已导入文章、探索对象、笔记和会话中的阅读线索补充兴趣。匹配覆盖标题、简述及可用主题词；同平台不同栏目合并参与交错，穿插其他方向，降低某一平台独占列表的机会。关闭个性化后仍可主动选择来源、关键词与排序。兴趣和屏蔽词保存在本地。

更新流程读取各启用来源，规范地址和条目，比较已有内容，分别统计新增与修改。重复读取保留现有列表；无变化时显示“暂无新增或修改”。本次更新入口只展示对应批次发生变化的内容。“最新发布”按可用发布时间安排内容，排序选择在下次启动恢复。来源失败与条目成功分别记录，其他来源可以继续使用。

封面读取订阅中的媒体资源或原网页提供的封面信息，保留来源；没有图片时使用文字卡片。应用不生成新闻封面。收藏、暂不感兴趣和来源筛选帮助用户控制后续浏览，详情页可以继续翻译摘要、打开原站，或选择取得全文加入资料库。

公开链接获取经过URL与重定向检查，限制可读取的资源和返回体大小。需要登录、访问受限或站点结构不支持时，用户可以回到原站，或导入自己取得的文件。微信公众号采用公开链接收集和网页读取方式，当前没有账号登录与私有文章抓取模块。

主要实现：app/discovery.py、app/discovery_sources.py和app/native/discover.py。界面示例见[发现与排序](../screenshots/discovery-updates-20261025/README.md)。

## 6. 全文接入与原文阅读

资料接入接受PDF、DOCX、文本、粘贴内容和公开链接。文件导入把内容转换为文章块，保留可用图片及定位。多文件导入逐项显示进度，停止后已完成资料继续保留。网页读取提取正文和安全富文本；直接PDF、arXiv及公开声明PDF的论文详情页进入论文读取流程，下载可用原件并提取内容。

“获取全文并加入资料库”与保存摘要分别处理。论文摘要作为独立内容类型保存；继续取得全文后，以全文文章参加阅读与检索。文章内容相同的重复接入复用已有资料和相关状态。划词时只取得上下文的记录保留片段身份，可在后续取得完整来源后补齐。

PDF提取按文本块组织正文，保留页面图像供核对。扫描资料可通过图像阅读；Word文档按段落和图片读取。原始论文PDF可从资料信息另存。正文追加、文件追加、文章改名、历史版本查看等操作均通过资料服务处理。

阅读器把原文与文章工具放在同一页面。Ctrl+F打开查找，Enter或F3前往下一处，配合Shift返回上一处，Esc关闭。选中文字可以标注、建立词语探索或写随文笔记；引用跳转按所属块和可见字符映射定位，富文本样式不改变原句对应关系。阅读位置按文章保存。

图片支持缩放、拖动、自适应和框选；归一化选区随文章保存。公式可在文章内展开查看；宽表格随窗口调整。本文问答位于侧栏，翻译从文章工具栏进入，导图和资料操作使用当前文章。阅读笔记导出可汇集原文、标注、问答依据、心得与译文。

主要实现：app/reader_source.py、app/paper_source.py、app/native/imports.py、materials.py、reader.py、images.py、find.py和mathtext.py。格式读取和界面状态分层处理，新增来源可复用同一文章与阅读流程。

## 7. 本地RAG与混合检索

RAG在这里指先从本地资料找到相关依据，再把问题与依据交给模型回答。文章入库后参与关键词检索，本地向量模型对文章正文和个人笔记建立增量索引。全库问答每次读取当前可用文章，新增资料自动加入；本文问答聚焦当前文章，用户可主动选择更小范围。

关键词检索对英文单词和中文双字片段分词，正文在段落边界附近切块，保留适当重叠。每块携带文章id、版本、标题、块id、起止字符、页码与原句。标题和正文共同帮助召回；抓取上下文以明确的片段类型参加检索。

语义检索使用Xenova/multilingual-e5-small的量化ONNX模型。文本分别加passage或query前缀，经分词、掩码平均池化和L2归一化获得向量；推理在本机CPU运行。索引切块兼顾模型长度，超长问题使用有界查询表示，文章分段保留全文。模型id和内容指纹进入索引状态，正文、标题、笔记变化后重新计算对应资料。

两类召回采用倒数排名融合：对同一候选累加各检索通道的排名贡献，再结合可用依据空间选择结果。这样可以把精确术语与相近表达组织到同一次检索中。明确包含多个问题时分别查找依据，再分配材料空间，避免第一个问题占满所有片段。

向量构建记录文档进度、失败原因与发布代次。构建期间资料变化会使旧结果失效，后续继续同步。模型缺失或向量不可用时保留关键词检索，并在索引状态中说明。个人笔记与原文分别标识，用户确认的模型整理笔记同样保留来源身份。

主要实现：app/retrieval.py、app/semantic_library.py、app/local_embeddings.py和app/library_assistant.py。本地向量模型承担查找工作；它与用于生成回答的联网模型分别配置和运行。

## 8. 问答、引用与上下文预算

本文会话围绕当前文章与阅读位置组织问题，资料库会话默认覆盖已入库资料。比较阅读可选择多篇文章，分别提取依据；模型回答要覆盖所选文章并给出各自引用。开启笔记范围后，笔记以个人内容参加检索，回答保持原文事实、个人理解和推断的区别。

请求由固定角色说明、有效历史、本次材料和问题组成。片段被编号为S1、S2等，携带所属标题和内容类型；模型在对应结论后引用这些编号。文章和历史回答作为材料处理。客户端先移除旧轮引用编号，再提供本次来源映射，避免把先前编号误作当前依据。

返回后，本地代码核对引用是否指向本次片段、原句是否存在、比较回答是否覆盖全部资料。首次结果缺少有效依据时，可用本次材料再修正一次。保存前重新计算资料状态，正文或已纳入笔记发生变化时保留问题并要求重新提问。点击引用回到对应文章和原句；历史会话保留当时的依据快照。

上下文预算控制一段会话可使用的输入、输出与历史空间。设置页采用预算滑轨、保存预设和恢复默认值。预算策略先为回答保留输出空间，再给本轮证据和历史分配余量；材料过多时缩小范围、提高预算或接续新会话。会话接续保存可回顾的历史与本地交接信息。

用量显示区分估算与供应商报告。估算依文本字符和消息开销计算，图片另作记录；API提供有效usage后采用报告值。界面不会把文本估算当成精确计费值。模型、推理强度与供应商支持情况由设置和客户端共同处理。

无相关依据时直接返回资料查找结果；问候等简单消息可以在本地回答。图片选区问题使用明确选择的区域，原文与模型解释继续保留对应关系。

主要实现：app/library_assistant.py、app/conversation_budget.py、app/context_usage.py和app/native/chat.py。

## 9. 文章翻译与任务恢复

翻译属于阅读工具。用户在文章工具栏选择源语言和目标语言，开始后对照阅读原文与译文。源语言支持自动识别，目标语言需明确选择；当前提供中文、英语、日语、韩语、法语、德语、西班牙语、俄语、葡萄牙语、意大利语和阿拉伯语等选项。

翻译状态按来源保存。文章译文关联文章标识；浮窗文字和发现摘要使用自己的来源标识。同一来源替换待译文字前提供选择，避免清空已有草稿或停止正在进行的任务。切换文章时恢复所属语言、输入、译文与进度。

长文按段落或句子边界分段，保留每个原字符。每完成一段即更新部分译文和检查点。检查点身份由语言、完整原文和模型配置形成摘要；恢复时核对身份和已完成分段，只复用当前输入的有效结果。改动原文、语言或模型配置后使用相应的新任务身份。

模型收到翻译方向和当前段正文，正文作为材料处理；输出要求完整译文，并通过客户端的完整响应检查。用户可停止、继续、复制或保存已完成内容。中断时保留有效分段，后续从有效位置继续；文章之间的译文相互隔离。

![文章工具栏中的语言选择与对照翻译](../screenshots/reading-tools-20261024/translation.png)

主要实现：app/translation.py和app/native/translation.py。全文导出通过阅读笔记流程纳入当前文章的译文。

## 10. 图片理解与导图生成

图片浏览在本地完成。用户选定整图或区域后才发起理解，选区按原图坐标裁切，识别描述和后续回答使用所选范围。设置中的图片能力检测向所选模型发送测试图，以实际回复判断是否可用。图片理解和图文导图使用支持图片输入的模型。

导图分正文和图文两种依据。正文模式阅读可提取文字；图文模式同时分析正文和选定图片，适合扫描页或图表占重要信息的资料。输入范围明确记录，生成结果关联文章版本和本次输入。

正文导图采用三个阶段：独立研读先抽取信息单元与逐字引用；生成阶段把信息组织为节点、层级、语义关系和划词绑定；复核阶段将草稿与原文及研读清单对照。复核重点包括信息覆盖、端点、方向、条件、否定和可选性，最多进行三轮纠错。组织树用于浏览结构，语义关系需要对应原文。

较长正文自动分段研读，逐段通过后缓存，再按原文顺序合并。完成部分、待核对草稿和阶段记录可在中断后恢复。缓存身份包含输入与模型配置，损坏、引用不符或缺少通过记录的分段会重新处理。重新整理清除当前输入对应的进度，其他资料继续保留。

原文引用核对容许换行和缩进的排版差异，再恢复实际原句；词语、数字或标点变化仍要重新核对。跨页引用定位修复只针对有问题的引用进行。分段之间只保留有原文支持的关系。任务显示阶段、分段与用时，停止或失败保留已完成内容和旧正式导图，新结果通过后才替换。

主要实现：app/article_map.py、app/long_article_map.py、app/multimodal_map.py、app/map_input.py、app/map_service.py和app/native/maps.py。模型复核是生成流程的一部分，用户仍可沿节点和关系回到原文查看依据。

## 11. 导图编辑、布局与完整导出

导图画布支持拖动、缩放、自适应和层级显示。较长导图先显示主题概览，选择有下级内容的节点后展开分支，再返回上层。浏览分支只改变可见范围，完整结构继续保留。节点和关系列表可查看对应原句，并跳回阅读页。

选中节点后，可以修改文字、新增子节点、调整上级或删除分支。上级选择支持查找，不能把节点接到自身或后代。删除前显示受影响范围，再移除该分支和相关关系。手动内容带有标记，修改已有内容时保存原文字和原文依据，便于区分材料结构与自己的补充。

关系编辑连接两个不同节点，保存关系文字和个人说明。手动新增关系不会附上未经核对的原文引用；已有关系的调整保留原关系供回看。树形层级和语义关系分别编辑，避免把整理顺序当成材料中的逻辑关系。

开启调整布局后拖动节点，松开保存位置，连线随节点移动。方向键可微调，Shift加大步长。文字、关系和布局随文章保存；重新生成使用新图的身份。撤销支持回退最近调整，恢复布局只改变位置，恢复原图回到生成版本。生成期间暂缓手动整理。

![手动编辑节点、分支与关系](../screenshots/map-structure-20261024/map.png)

导出支持完整PNG、SVG和带节点、关系及依据的Markdown，采用当前文字和结构，图形导出保留布局。导出范围覆盖完整导图，个人补充一并标识。主要实现：app/native/map_editor.py、maps.py、app/map_customization.py、app/map_export.py及相关导出模块。

## 12. 阅读笔记与内容管理

笔记可以围绕文章、原文块和阅读问题组织。用户选中文字标注后写心得，也可以在阅读侧栏保存较长笔记；经确认的模型回答可以另存为笔记。笔记保存所属文章、版本、位置与来源身份，可在笔记管理按文章查找和继续编辑。

原文标注记录实际引用和字符范围，阅读器通过可见正文映射显示。返回资料时恢复阅读位置和当前对象，修改文章后核对对应版本。阅读记录、文章笔记、探索对象和对话分别保存，用户可以按自己的整理方式继续使用。

内容管理统一索引文章、笔记、词语或图片探索、问答、计划、主题、导图、阅读记录、标注和草稿。当前与先前对话均可搜索，消息、未完成问题和引用在页面内展开。点击来源返回所属文章或笔记，再返回列表时保留筛选与滚动位置。

历史依据保留回答当时的快照。原资料已删除时仍可查看已有记录中的依据文本；版本或位置不一致时明确提示重新核对。查看和返回属于本地操作，不发起新的模型生成。

删除操作按对象展示影响。删除对话清空该会话的消息、草稿和回顾，独立笔记保留；删除主题解除文章组织关系；删除文章与历史版本会同时移除关联的译文、标注、笔记、导图和问答。用户据影响范围决定是否继续。

阅读笔记导出把原文、标注、随文心得、问答引用与本文译文组织为Markdown，方便在外部编辑器继续整理。导出与导图导出承担不同任务：前者保留阅读过程，后者保留结构和关系。

主要实现：app/study_hub.py、app/reading_annotations.py、app/content_management.py、app/reading_export.py，以及app/native/notes.py、content.py和content_detail.py。

## 13. 学习计划、今日与探索统计

学习规划接收自然语言目标、日期、可用时间和偏好。用户可以描述要学习的主题、准备阅读的资料和每日时段，小探结合当前日期、已有任务、文章标题与长度提出安排。信息已足够时直接给出可修改的建议；确有关键缺口时再询问必要问题。

模型返回计划说明、必要问题和任务数组。任务包含标题、具体产出、目标、日期、开始时间、分钟数和可选文章id。保存前，本地代码检查结构、时间范围、任务长度、资料归属、可用时段、过去时间及跨午夜情况，随后统一检查已有任务与批次内的冲突。

整批计划在同一事务中保存。生成期间日程发生变化时，本地保存检测到冲突，会把最新安排、原草案与冲突信息交回规划器。第二次只重新分配时间，必须覆盖全部原任务，保留任务内容和时长；仍无法安排时继续询问可用时间，避免留下半份计划。

计划支持查看待办、标记完成、调整和关联资料，完成后在今日与探索统计中展示。部分任务可以按已有内容拆分为后续行动；已完成或用时过短的任务采用相应限制。用户可以从计划返回相关文章继续阅读。

## 14. 浮窗、主界面与统一视觉

浮窗与主界面构成一套桌面阅读系统。浮窗从其他应用取得选区、上下文和可识别来源，完成即时解释与保存；主界面提供发现、全文阅读、资料问答、翻译、导图、笔记和计划。外部抓取内容首先保留其实际范围，取得全文后再进入完整文章流程。

两个进程共同读取资料位置、模型设置和阅读外观。颜色来自共享主题资源，支持clay、violet、parchment、blue、forest、ocean六套配色及明暗模式。主界面和浮窗定期读取持久化偏好，切换外观后在各自刷新周期内更新。共享资料使保存的词语、来源与内容可以被另一入口继续使用。

这种协作分别处理持久化同步和窗口跳转。主界面打开文章不强制浮窗显示同一页面，浮窗带入的翻译文字按外部来源保存；返回原文的请求携带文章或对象身份。本地交接记录完成消费后清理，超过有效时间的请求失效。

重复启动相同构建时呼出已有窗口；选择不同构建时，新版本等待旧实例正常保存退出后接管。启动与退出同时考虑主界面和划词组件，存储迁移则在组件完全停止后应用。构建流程把主界面、浮窗程序和UIA辅助库纳入同一次交付，并核对源码指纹。

主界面使用无边框窗口和统一主题控件。按钮、下拉、表单、确认面板与文件面板沿用应用配色；阅读工具嵌入当前流程，常用操作在页面内完成。滚动区、侧栏和编辑区分别管理尺寸，保存与取消保留在可访问位置。页面文案说明操作和结果。

页面控制器与后台任务分别管理生命周期。切换功能后，结果交回所属任务，当前文章、草稿、语言和滚动位置按资料恢复。小窗口模式维持当前版本的适配范围，后续继续优化。主要实现：app/capture_bridge.py、app/native/handoff.py、instance.py、surfaces.py、widgets.py及app/reading_preferences.py。

## 15. 模型请求、停止与后台预读

模型客户端统一处理接口地址、模型、推理强度、密钥、文本或图片输入。供应商支持的参数由客户端兼容规则组织；图片能力通过实际检测确认。应用内业务服务构造任务，传输模块负责网络与响应，请求管理器负责资源和时间。

RequestSupervisor保存排队、运行、完成、错误和取消等状态。相同进行中的请求可共享一次执行，订阅者分别等待结果；前台操作优先于后台预读。并发总量、同一路由占用和队列长度有界，避免重复点击或慢请求持续增加工作线程。

等待时间拆为排队与实际调用，排队超时和任务期限分别处理。临时连接错误、限流或可恢复服务故障在预算内重试；持续失败进入恢复等待。用户停止后设置取消标记，业务层检查任务状态，已取消结果不继续写入所属资料。

底层连接、DNS或套接字可能无法即时退出，取消后的传输在实际结束前仍占原有槽位。管理器据真实执行状态释放资源，避免停止一次后立即产生无限替代请求。用户可以继续阅读，界面呈现所属任务当前状态。

后台预读在文章打开后准备后续研读所需内容，结果与输入身份匹配才复用。切换资料、模型配置或重新整理时，分别处理缓存与任务状态。后台工作接受前台优先级和用户取消约束，暂时中断保留已完成的有效进度。

记录保存任务种类、阶段、用时与脱敏错误等运行信息。接口密钥不进入这些状态。业务层通过进度回调显示正在查找依据、翻译分段、核对导图或保存计划；统一管理请求资源，同时保留各业务自己的检查点。

主要实现：app/request_supervisor.py、app/api_client.py、app/api_transport.py、app/map_preload.py和app/native/progress.py。

## 16. 意图控制与Prompt设计

开发协作先描述用户要完成的行为，再提供相关模块、现有数据结构、触发步骤和期望结果。例如，资料库问答的目标是已入库文章默认可查阅；翻译的目标是语言、译文和任务跟随当前文章；主界面与浮窗的目标是共享配置和资料。每个目标对应数据归属、界面操作与可检查的保存结果。

协作上下文按任务组织。检索修改提供文章结构、索引和引用规则；请求修改提供传输、队列、取消和超时关系；计划修改提供已有日程、可用时段、事务和界面状态。页面显示放在控制器，业务规则放在服务，持久化沿用存储层。产品行为决定修改范围，代码职责约束生成实现。

应用内模型任务也采用明确契约：固定说明定义任务，原文、历史、个人笔记和外部页面作为带身份的材料；代码先确定输入范围，再验证输出结构和保存条件。下面的示例节录实际实现，完整指令保留在源码，具体协作过程见下一章。

### 资料问答：范围、证据和引用

app/library_assistant.py中的角色说明包含：“只依据本次材料回答，每个有依据的结论附[S编号]”“个人笔记不可称为原文或已验证事实”“划词上下文仅代表抓取片段”。本次材料逐条标记原文、个人笔记或抓取片段，并附标题与S编号；当前问题与有效历史随后加入请求。

这套Prompt把“回答资料问题”进一步约束为“使用本次证据回答，并标明结论出处”。后处理通过referenced_evidence校验引用，比较阅读额外核对覆盖资料集合。生成期间的资料修改由source_revision再检查，Prompt和本地代码共同维护依据归属。

### 翻译：方向和正文身份

翻译说明给出源语言、目标语言和完整翻译任务，正文被当作翻译材料。前置validate检查语言与长度，chunks保存原字符并分段。检查点按原文、语言和模型配置形成身份，后续恢复先匹配身份。模型完成当前段的语言转换，代码负责段落接续和文章隔离。

<!-- pagebreak -->

### 导图：分阶段任务与语义约束

app/article_map.py为研读、生成、复核分别构造任务。研读者独立从原文提取信息与逐字quote；生成器根据清单组织节点与关系；复核者检查遗漏、方向、条件和否定。结构契约包含nodes、relations、bindings等字段，引用和节点关系再由本地校验器检查。

例如，“完成A后可以执行B”应保留顺序和“可以”的可选性。单个完整动作可以作为节点，组织分支不自动构成因果边；原文没有的关系不通过连线补写。纠错携带明确条目、旧草稿与反馈，修正指定问题并继续保留其他已通过信息。这把抽象的“生成准确导图”拆为可追踪的中间结果。

### 学习规划：结构化输入与事务约束

规划输入将request、conversation、now、articles、existing_tasks和可用时间组织为JSON。app/study_advisor.py规定返回message、questions与tasks；能够规划时给出任务，确实缺少关键信息时只问必要问题。任务字段包含日期、时间、时长、产出和文章id。

日程冲突时追加previous_proposal与conflict，第二次只返回task_index、date和time。本地revised_schedule要求覆盖全部原任务，再由可用时间检查和StudyHub事务保存。日期、资料id、时长和冲突规则在模型之后继续核对，生成文本不能绕过保存条件。

## 17. 三条实际开发协作链

### A：从资料库外观到本地检索

原始需求提出主题库房、文章查看、心得笔记和RAG问答，并进一步要求“开始建立真正的RAG库”。这一目标被分解为文章与主题关联、笔记随文保存、本地向量模型、关键词与语义召回、上下文预算和原文引用。

开发上下文包含文章块、原有检索和会话服务。实现沿用既有文章存储，在独立模块中构建向量与混合检索，再由资料问答调用。后续反馈指出新建主题和拖动文章时出现fetch失败；修复继续定位本地服务与界面生命周期，并补齐用户可理解的错误表达。

这条链的关键在于把“有一个资料库页面”落实为“资料能参与检索、被引用，并可按主题继续阅读”。原始往返、问题反馈与修改说明保留32条消息。代码节点：[bcf05f8](https://github.com/bsk865/ExplorerDict/commit/bcf05f8)。[需求与实现记录](原始对话/A-本地RAG与本机分类.md#early-118) · [故障反馈](原始对话/A-本地RAG与本机分类.md#late-000)。

### B：从等待问题到受管理请求

用户询问“一篇300多字的文章对于输出速度快的模型来说为什么会等待这么久”，随后提出请求管理机制，处理同一请求卡顿和长时间堵塞。相关上下文由业务等待扩展到排队、传输、分阶段生成、取消与预读。

实现采用统一RequestSupervisor，把请求身份、前后台优先级、订阅者、期限和实际工作线程分开管理。相同任务合并，前台等待优先，临时错误按预算重试。取消保留真实传输槽位直到退出，避免慢连接不断生成替代线程；业务检查点保留有效研读进度。

用户截图和后续反馈推动错误分类、实际用时与恢复状态继续调整。结果是请求资源与业务状态能够分别观察和控制。完整记录保留33条消息与2张反馈附件。代码节点：[e24cfcd](https://github.com/bsk865/ExplorerDict/commit/e24cfcd)。[等待反馈](原始对话/B-后台预读与请求重试.md#late-038) · [请求管理需求](原始对话/B-后台预读与请求重试.md#late-041)。

### C：从自然语言目标到学习行动

用户希望计划面板包含时间和天气，由小探理解需求、自动组织计划，并加入探索统计以获得条理感和成就感。后续截图反馈“这块看着有些乱而且看不懂”，进一步要求任务完成进度条。

开发把目标分为对话式规划、任务保存与状态展示。模型侧接收当前日期、可用时间、资料和已有任务；代码侧核对结构、时间和资料关联，在事务中整批保存。界面侧提供待办、完成反馈和统计，并把天气城市作为持续保存的偏好。

后续集成又处理生成期间日程变化：保留原任务的内容与时长，依据最新日程仅重新安排时间。这项规则由本地保存和第二轮Prompt共同约束。协作记录保留81条真实用户与AI消息及3张附件；自动调度文本已排除，公开文本与摘要索引可逐条核对。代码节点：[860fd01](https://github.com/bsk865/ExplorerDict/commit/860fd01)。[原始需求](原始对话/C-学习规划与任务进度.md#early-006) · [界面反馈](原始对话/C-学习规划与任务进度.md#early-040) · [进度反馈](原始对话/C-学习规划与任务进度.md#late-069)。

三条记录分别对应检索、请求管理和学习规划模块，保留需求、方案、反馈、修复与提交。导出工具检查消息身份、索引对应和公开文本SHA256；可运行tools/export_prompt_chains.py的--check-public检查146条公开消息。

## 18. 运行环境与可复现性

Windows用户可下载免安装ZIP，解压完整目录后启动探索词典-原生版.exe。运行环境和本地向量模型随包提供。首次使用可导入文章、阅读和记笔记；问答、翻译、导图和规划在用户保存模型配置后运行。

源码环境统一为Windows10/11 x64、PowerShell5.1+和CPython3.14 x64；本次记录使用3.14.5。requirements.txt固定运行依赖，tools/build-requirements.txt固定打包依赖，tools/document-requirements.txt提供文档构建依赖。准备脚本创建新的.build-env，安装依赖，下载并校验模型，再编译Windows UIA辅助库。

```powershell
git clone https://github.com/bsk865/ExplorerDict.git
cd ExplorerDict
powershell -ExecutionPolicy Bypass -File scripts/setup-repro.ps1 -SkipTests
.build-env/Scripts/python.exe native_desktop.py
```

模型固定为Xenova/multilingual-e5-small，revision为761b726dd34fb83930e26aab4e9ac3899aa1fa78。远端onnx/model_quantized.onnx下载到本地models/multilingual-e5-small/model_quantized.onnx，tokenizer.json保存到同目录。准备脚本按SHA256确认完整文件，模型缺失时可使用-SkipModel先运行关键词检索。

| 文件 | SHA256 |
| --- | --- |
| model_quantized.onnx | f80102d3f2a1229f387d3c81909990d8945513e347b0eab049f7de3c6f98c193 |
| tokenizer.json | 0b44a9d7b51c3c62626640cda0e2c2f70fdacdc25bbbd68038369d14ebdf4c39 |

环境变量模板scripts/repro-env.example.ps1可指定独立资料目录和存储配置，模型接口与密钥在设置中保存。QT_QPA_PLATFORM=offscreen用于自动化离屏检查，正常桌面启动前移除。源码启动检查使用新资料目录，验证UIA辅助库加载、本地384维向量推理、文章导入重读和原生窗口渲染，不调用模型API。

可重复的部分包括源码提交、固定依赖、模型版本与摘要、资料关联和保存规则。联网来源随站点更新，模型生成文本随供应商与输入变化；复现应核对引用、状态和保存结果。软件提供公开文本与自编示例用于重复阅读流程。

完整步骤、独立目录计时及运行条件见[源码运行](../复现指南.md)和[源码环境运行记录](../源码环境运行记录-20261025.md)。记录说明操作系统与Python前置条件、缓存情况、下载、环境创建和启动范围，以实测结果描述准备时间。

## 19. 配置、隐私、构建与维护

设置提供接口地址、可编辑模型选择、推理强度和API密钥，以及显式的图片能力检测。上下文预算使用滑轨、保存预设和恢复默认值。配置供主界面与浮窗共同读取；密钥使用Windows DPAPI保存，换电脑时重新填写。模型服务接收相应问题和所需材料，处理方式遵循用户选择的服务政策。

资料默认保存在程序目录data，也可在设置中选择新的空文件夹。变更先记录目标，应用完全退出并等待组件停止后执行迁移，原目录保留。备份时先退出主界面与浮窗，再复制完整资料目录；升级保留已有资料与存储位置配置。

程序通过PyInstaller构建原生主界面与划词组件，重建UIA辅助库，核对组件指纹并包含共享主题、图标与向量模型。发布检查排除用户数据库、密钥和本机存储路径。Releases提供Windows-x64.zip及SHA256SUMS.txt，源码与构建记录对应保存。当前以免安装包分发；安装器系统注册权限与发布者签名继续完善。

开发按场景需求、模块实现、实际使用反馈、定向修改和版本交付推进。修改关注所属行为：资料相关核对文章与版本，引用相关回到原句，界面相关检查窗口和滚动，构建相关核对两个入口。三条核心协作链与模块提交公开保存，旧规格和运行结果按日期归档。

后续方向包括复杂图文资料、较长导图的稳定性、长时间跨应用使用、窗口尺寸适配及早期版本升级。当前交付包含阅读、发现、翻译、问答和学习整理主流程，具体版本进展见[版本进展](../开发状态.md)。
